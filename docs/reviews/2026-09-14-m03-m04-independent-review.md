# M03/M04 独立产品与架构审阅 · 2026-09-14

## 结论

M03/M04 已构成可演示的 Wave 1 基础闭环：行程按天展示、三态打卡、增删；账本记账、预算联动、分类占比和每日趋势。原型 B 的紫/橙/黄色板、圆形节点、胶囊和弹簧反馈与现有 token 一致；SVG 图标在 iPhone 17 Pro/iOS 26.3 模拟器中实际显示正常。`packages/shared` 放纯逻辑和 schema、`packages/ui` 放主题及 Icon、`apps/mobile` 放平台数据层与页面，方向合理。未新增原生依赖或变更实体 schema。

独立核验发现并已修复：

| 问题 | 影响 | 修整 |
|---|---|---|
| 分类百分比逐项四舍五入 | 三等额分类可显示 33%+33%+33%=99%，违反 M04 AC-7 | 最大余数法分配整数百分比，合计恒为 100%，保留金额降序；补边界测试 |
| 预算状态以四舍五入后的百分比判断 | 79.6% 会过早触发 ≥80% 警告，违反 M04 AC-6 | 状态按未舍入的真实金额比判断，展示百分比仍为整数；补边界测试 |
| Web 删除旅程只软删除清单 | 孤立行程和账目仍可被直接路径读到，与 SQLite 行为不一致 | Web 同步软删除行程与账目并写入同步队列 |
| 添加/预算表单的错误仅渲染在 Modal 后方 | 用户输入非法值时看不到错误，违反 M03 AC-8、M04 AC-2 | 错误同步显示在当前弹层，重新打开时清掉旧错误 |
| M03/M04 同一入场动画重复实现 | 动效阈值或无障碍改动容易分叉 | 抽为 `CascadeIn` 单组件，两页共用 |
| 600ms 彩带标准与 800ms token/900ms 展示不符 | M03 AC-5、M04 AC-3 时长不符，减弱动效仍出现静态彩带 | 两页反馈统一 600ms，减弱动效不渲染彩带 |
| 快速连点打卡或提交 | 可发起并发写入，产生状态乱序或重复账目 | 为单条状态切换及新增表单加进行中保护，避免重复提交 |

## 产品决定点（建议下一次由 Simon 定）

1. **行程编辑**：当前录错时间/地点只能删除重建，会丢打卡状态和创建时间。建议将“编辑时间/内容/备注且保留 ID/状态”列为 M03 下一小版本 P1；本次没有扩范围改变尚未正式评审的需求。
2. **补记账日期**：当前每日趋势按 `createdAt` 本地日期统计，旅后补记会落在补记当天。建议若“旅行记录”定位需要追溯日期，先评审新增消费日期字段与迁移方案；不要直接改冻结实体。
3. **演示旅程和正式数据**：演示数据采用独立 settings 标记，删除旅程后不重种是正确体验；但若只重置 SQLite 而保留 MMKV，空库也不会再种。建议未来把演示生命周期标记放进同一个事务域，避免测试/迁移时分裂。该问题不影响用户自己创建旅程。
4. **账本图表**：现有 SVG 折线足以满足本期静态趋势。若以后要求跨很多天的横轴、可触摸读数或筛选，独立评审图表组件或缩放策略，避免继续把图表逻辑堆在 `ledger.tsx`。
