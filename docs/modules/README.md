# modules/README.md · 模块文档模板与生命周期说明

> 本文档说明 `docs/modules/` 下每份模块文档**怎么写、何时冻结、谁批准**。起草任何模块文档（Mxx-\*.md）前必读；流程全貌见 [../WORKFLOW.md](../WORKFLOW.md)，模块清单见 [../MODULES.md](../MODULES.md)。

## 文件命名与状态

- 命名：`Mxx-kebab-case-slug.md`（如 `M00-foundation.md`），编号与 [../MODULES.md](../MODULES.md) 严格一致。
- 每份文档开头标注当前状态，与 [../ROADMAP.md](../ROADMAP.md) 看板保持一致（看板是唯一状态源，文件内状态是镜像）。

## ① 需求

- AC-2：……

## 段落冻结与批准一览

| 段落 | 谁写 | 何时冻结 | 谁批准 |
|---|---|---|---|
| ① 需求 | 起草 agent | 需求评审门通过 → 需求冻结 | Simon |
| ② 技术调研 | 起草 agent | 不冻结，可被③引用修正 | —（随③一并评审） |
| ③ 技术方案 | 起草 agent | 技术评审门通过 → 契约冻结 | Simon |
| ④ 任务清单 | 起草/施工 agent | 施工中可增补，不可删已完成的任务 | — |
| ⑤ 施工记录 | 施工 agent | 不冻结，append-only | — |
| ⑥ 验收 | 验收 agent | Simon 签字 → 模块完成 | Simon |

## 纪律

1. 需求段未冻结，禁止填写③之后的实质内容（可留占位）。
2. EARS 每条必须能被验收 agent 独立执行核验；写不出 WHEN/SHALL 的需求就是模糊点，进模糊点清单。
3. 施工者不验收自己的模块。
4. 文档只增不改历史段落——需求/方案变更走重新评审，在对应段落追加"变更记录"而不是涂改。
