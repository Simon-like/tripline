# 对比报告 · 旅行小结重做（G1）

> 2026-09-17。用户点名："旅行小结很文字化很一般"。本报告对比现状与三个候选方向，供 Simon 拍板。**注意：小结现状是 M07 已定义的需求形态（返程页统计弹层 + 纯文字复制），任何升级都属需求变更，须重走 M07 评审门。**

## 现状实录（基线）

`JourneySummarySheet.tsx`（72 行）：BottomSheet → 标题「把这一程，收进回忆」→ 3 个淡紫统计胶囊（已去行程 x/y、见闻 n、照片 n）→ 一行预算文字 → 白卡装 9 行纯文字全文 → 「复制文字总结」按钮。

痛点清单：
1. 图形化元素为零——无图表、无照片、无主题色（连现成的 journey palette 都没用）。
2. 数字重复出现两次（胶囊一次、文本墙一次）。
3. 混入工程向文案「照片数按手账中的记录统计，不代表本机可读取数量」。
4. 零动效：数字不滚动、内容不逐项入场。
5. 分享物是纯文字——旅行结束这一全年仅 2-5 次的情绪峰值时刻，产出物没有"可晒性"。

## 候选方案对比

| 维度 | 方案 A · 原地图形化（轻改） | 方案 B · 逐屏故事流（推荐） | 方案 C · 单张成就卡（极简） |
|---|---|---|---|
| 形态 | 保持弹层，内容重排：主题色封面头 + 环形完成度 + 迷你趋势图 + 照片墙 + 精简文案 | 全屏 5–7 屏横滑故事：封面 → 大数字 → 极限时刻 → 账本洞察 → 照片/金句 → 人设标签 → 分享页 | 直接生成一张 1080×1350 成就卡，弹层内预览 + 分享/保存 |
| 用户感知 | "变精致了" | "哇，这是我的旅行电影"（Wrapped 级） | "可以立刻晒" |
| 实现成本 | 低（1 个组件重排，全部复用现有：palette/RollingNumber/ProgressRing/折线） | 中-高（FlatList snap 分页 + 离屏截图分享 + 人设标签规则引擎） | 中（离屏渲染 + view-shot，但无叙事） |
| 新依赖 | 无 | react-native-view-shot 或 Skia snapshot（需评审） | 同左 |
| 需求变更幅度 | 小，AC-1~5 结构不变，可视为呈现增强 | 大，需重写 M07 需求 + EARS | 中，追加"图片分享"AC |
| 风险 | 低 | 分页交互在弹层 vs 全屏需抉择；截图双端一致性需验证 | 单卡信息密度有限，叙事感弱 |
| 与"纯文字复制"AC 的关系 | 保留复制按钮 | 保留文字通道（导入/纯文本场景仍需要） | 保留 |

## 推荐路径：A 先行 → B 立项

1. **第一步（P1，无需评审争议小）**：按方案 A 原地图形化——套旅程 palette 封面、ProgressRing 复用为"行程完成度环"、账本迷你占比条、照片 3×2 拼版（±3° 轻倾斜，纸感）、数字全改 RollingNumber 逐项入场、删除工程文案（挪到二级说明）、文字稿精简为 4 行。零新依赖、零契约变更。
2. **第二步（P2，走 M07 评审）**：方案 B 逐屏故事流立项。关键设计决策预研结论：
   - 人设标签规则引擎放 `packages/shared` 纯函数（如"花费 < 预算 70% 且行程完成 > 90% → 精打细算的暴走族"），可单测。
   - 极限数据钩子（最早行程时刻/最大单笔开销/照片最多的一天）为纯数据查询，成本极低、记忆点最强，必做。
   - 分享图用 Skia snapshot 优先（已在栈，避免新原生依赖）；Skia 不满足再评 view-shot。
   - 收尾屏"下一站想去哪"许愿位，低成本高情感。

## 兼容性核对

- 双主题：全部消费 token 与 journey palettes（明暗成对已有）。✅
- 减弱动效：翻页保留吸附、取消入场级联，瞬时切换。✅
- 红线：不加第六 Tab（保持弹层/全屏 Modal）；只动 transform/opacity。✅
- 契约：方案 A 零变更；方案 B 人设标签若入 shared 需冻结评审。⚠️
- AC-2「无记录不虚构成果」：人设标签与极限数据在空数据时整体降级为温馨空态。✅
