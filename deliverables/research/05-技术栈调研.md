# 旅迹 TripLine 技术栈调研纪要（RN/Expo + NestJS + Monorepo，2025–2026）

## 1. Monorepo 工具选型

Expo 自 SDK 52 起对 monorepo 提供一等支持：`expo/metro-config` 自动检测 workspaces 并配置 Metro，不再需要手写 watchFolders / nodeModulesPaths。pnpm 下必须在 `.npmrc` 配置 `node-linker=hoisted` 和 `public-hoist-pattern`（`*expo*`、`*react-native*` 等）。

- **纯 pnpm workspaces**：零成本起步，pnpm 9+ catalogs 可统一锁版本，但无任务编排与缓存。
- **Turborepo 2.x**：轻量任务编排 + 远程缓存，`--filter` 语义贴合 apps/* + packages/*，配置成本最低，是 Expo + NestJS 异构双 app 组合的主流选择。✅ 推荐
- **Nx 20+**：能力最强但心智负担重，小团队过度设计。

**结论：pnpm workspaces + Turborepo**。参考：byCedric/expo-monorepo-example。

## 2. 前后端共享数据结构

`packages/shared` 放 Zod schema + `z.infer` 推导类型，成熟主流。NestJS 侧用 nestjs-zod：`createZodDto` 从共享 schema 生成 DTO，全局 `ZodValidationPipe` 请求校验，`ZodSerializerInterceptor` 响应校验 + 自动生成 Swagger。

打包注意点：**shared 包直出 TS 源码**（`"exports": { ".": "./src/index.ts" }`），不预构建。Metro 能直接编译 workspace 内 TS 源码；Nest 侧 dev 用 tsx/SWC。shared 包必须保持"零原生依赖、零平台 API"。

## 3. Expo 现状

- 当前最新稳定版 **SDK 55（2026-02 发布，RN 0.83 + React 19.2）**；**SDK 55 起 New Architecture 强制开启且不可关闭**。Expo Go 只支持新架构。
- **Expo Go vs development build**：含自定义原生代码的库（MMKV、Rive 新运行时、Skia）以及推送通知、深链等在 Expo Go 里不可用/失真。**本项目 V1 即以 dev build 为开发基线**。
- **EAS Build** 云打包成熟，为默认路径；Android targetSdk 36（强制 edge-to-edge）。Monorepo 下注意 `.easignore` 不能排除 packages/*。

## 4. 动画与交互栈

- **Reanimated 4.x** 是当前主线（配对 react-native-worklets），只支持新架构。4.0 起 spring 物理重写：推荐只指定 `duration` + `dampingRatio`，行为可预测——契合 Material 3 Expressive 弹簧语言。另有 CSS animations/transitions 声明式 API（状态驱动）与 shared value + worklet（手势/滚动驱动）。
- **Gesture Handler 2.3+** 支持 Fabric，与 Reanimated 标准搭配。
- 庆祝动效：线性播放用 lottie-react-native（控制 JSON 体积）；粒子/彩带推荐 **@shopify/react-native-skia** + Reanimated 手写；需要状态机交互式动效可用 Rive（需 dev build）。
- 图表：**victory-native（XL 系，Skia + Reanimated，GPU 60fps）** 为当前推荐；react-native-chart-kit 已停更不推荐；react-native-svg 13+ 支持 Fabric 作为自绘底层。

## 5. 本地优先数据层

主流组合：**expo-sqlite（领域数据）+ react-native-mmkv（设置/标记/同步游标）**。MMKV 基于 JSI 同步读写约 30 倍于 AsyncStorage，但无查询索引；AsyncStorage 有 6MB 上限只适合原型；Realm 已被弃用，不选。expo-sqlite 有同步/异步双 API、支持 WAL，可搭 Drizzle SQLite 驱动。

**为云同步预留的本地 schema 约定（V1 就落地）**：`id` 一律 UUID v4 客户端生成；每行带 `createdAt`/`updatedAt` 毫秒时间戳、`deletedAt` 软删除（tombstone）、`schemaVersion` 字段；写操作记录变更日志表（sync queue）。图片用 expo-file-system 存沙盒目录、DB 只存相对路径；expo-image-manipulator 入库前压缩缩放转 JPEG。

## 6. iOS/Android 双端兼容要点

- Android 自 targetSdk 36 起**强制 edge-to-edge**，`StatusBar backgroundColor` 已移除，必须用 react-native-safe-area-context 的 insets，禁止硬编码状态栏高度。
- 字体：两端默认渲染差异明显，用 expo-font 打包自定义字体并统一 fontFamily + lineHeight。
- Android 返回键用 BackHandler/导航集成，Modal 与底部抽屉要单独处理。
- 键盘：iOS `KeyboardAvoidingView behavior="padding"`，Android `adjustResize`，两端分别真机验证。
- 深色模式：useColorScheme() + 设计 token 双份，splash/状态栏/导航栏跟随主题。
- 平台 API 坑：阴影（iOS shadow props vs Android elevation）、LayoutAnimation Android 需额外开启、日期/数字本地化差异、低端 Android 动画掉帧需降级策略。

## 7. NestJS 侧

- 全局 ZodValidationPipe 消费 shared schema，Swagger 自动从 Zod 生成——前后端契约单一来源。
- ORM：**倾向 Drizzle**（schema 纯 TS，可入 monorepo 共享图，drizzle-zod 可生成 Zod schema，轻量无 generate 步骤）；Prisma 7 亦可（已去 Rust 引擎），看重 Studio 工具链时选。
- "导出码 → 云同步"演进：V1 导出码本质是 `{schemaVersion, payload, checksum}` 编码串；V2 演进为 `POST /sync/pull?since=<cursor>` + `POST /sync/push`（变更数组含 id/updatedAt/deletedAt），冲突起步用 last-write-wins（按 updatedAt），服务端存 serverUpdatedAt 作游标。导出码导入 = 一次匿名 push。

## 推荐 monorepo 结构

```
tripline/
├── apps/
│   ├── mobile/        # Expo (RN) App，唯一面向用户的端
│   └── api/           # NestJS（V2 加入）
├── packages/
│   ├── shared/        # Zod schema + z.infer 类型 + 常量/枚举 + 导出码编解码，零平台依赖，TS 源码直出
│   ├── ui/            # RN 侧设计系统组件（Bento 卡、弹簧动画封装）
│   ├── config/        # tsconfig.base、eslint/biome、design tokens
│   └── db/            # V2：Drizzle schema
├── pnpm-workspace.yaml
├── turbo.json
└── .npmrc             # node-linker=hoisted + public-hoist-pattern
```

## 技术选型结论表

| 领域 | 选型 | 理由 | 风险 |
|---|---|---|---|
| Monorepo | pnpm + Turborepo | Expo 官方一等支持；Turbo 轻量 | pnpm 需 hoisted 配置 |
| 共享类型 | packages/shared + Zod | 校验+类型单一来源 | 须保持零平台依赖 |
| 移动端 | Expo SDK 55 / RN 0.83 | 当前稳定版，新架构强制 | 老库不兼容即报错 |
| 开发基线 | Development build + EAS | MMKV/Skia 都需原生代码 | 首次构建成本高 |
| 动画 | Reanimated 4 + Gesture Handler + Skia | 新弹簧 API 契合 M3 Expressive | worklet 学习曲线 |
| 图表 | victory-native (Skia) | GPU 60fps，活跃维护 | 依赖链较长 |
| 本地存储 | expo-sqlite + MMKV | 结构化 + 高速 KV | 同步逻辑自研 |
| 后端 ORM | Drizzle + PostgreSQL | TS 原生 schema | 生态比 Prisma 年轻 |
| 校验集成 | nestjs-zod | DTO/Pipe/Swagger 一体 | 第三方包依赖 |

## V1 → V2 数据迁移策略

1. V1 本地 schema 即带 UUID、updatedAt、软删除、schemaVersion；分享码含版本号与校验和。
2. V2 上线提供"导入导出码 → 注册账号 → 首启全量 push"路径：本地数据原样上行（id 不变，天然幂等），服务端按 updatedAt last-write-wins 合并。
3. schema 演进走版本化迁移：本地 SQLite 迁移脚本升 schemaVersion；服务端拒绝低版本 payload 或做 upcaster。分享码格式 v1 永久可读。

## 双端兼容红线（10 条）

1. 禁止硬编码状态栏/刘海高度，一律 useSafeAreaInsets()。
2. 所有文本必须指定自定义字体与显式 lineHeight。
3. Android 硬件返回键必须覆盖所有 Modal/抽屉/深层页面。
4. 键盘避让两端分开配置并分别真机验证，输入框被遮挡即 blocker。
5. 动画闭环必须跑在 UI 线程（Reanimated worklet / Skia），JS 线程动画不可接受。
6. 所有动画尊重系统"减弱动态效果"（Reduce Motion）设置。
7. 原生依赖必须全部通过 React Native Directory 新架构检查。
8. 深色模式不是可选：颜色全部走 token，禁止散落硬编码色值。
9. 图片入库前必须压缩并控制分辨率，DB 只存路径不存二进制。
10. Expo Go 只做原型演示；含 MMKV/Skia/推送的功能必须以 dev build 验证，发布前双端真机（含一台中端 Android）全量回归。
